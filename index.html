rollnw

rollnw is a C++ framework for RPG tools and runtimes, inspired by Neverwinter Nights and growing toward a modern authored game and toolset.

The project is in active development. Pin a Git revision and rebuild consumers when updating; APIs and the C++ ABI can change. See the release guide for snapshot and tool versioning.

nw

The shared C++ library for content formats, resource management, game objects, and rules. Its renderer brings NWN and glTF assets into a common runtime with PBR materials, skinned animation, particles, lighting, and shadows. These libraries underpin the tools below and can be used in other applications.

smalls

A statically typed, embeddable scripting language for game rules and tooling. Modules, generics, arrays, and maps support reusable scripts that connect to the library through native functions. The VS Code extension provides syntax highlighting and language-server support for writing and navigating Smalls code.

client

The module viewer and authoring workbench, installed as rollnw-client. Import a module into an editable project, explore its areas and resources, and edit objects and terrain with previews, undo, and save. Focused editors cover creature appearance and progression, item properties, inventory, and other supported object data.

Watch the demos: Overview · Area Editing · Item Interactions

mudl

A model and effects viewer for NWN and glTF assets. Inspect model hierarchies, play animations and effects, and check materials through the shared renderer. Its command-line tools also produce repeatable screenshots, turntable sequences, and fixed-step rendering benchmarks, including offscreen runs.

Build

Requires CMake 3.21+ and a C++20 compiler. Renderer tools (rollnw-client and mudl) run on Linux and Windows via Vulkan, and on macOS (Apple Silicon) via native Metal.

Linux binary packages built from current source, including the VS Code language server, target Ubuntu 24.04 or a compatible runtime. GCC CI uses Ubuntu's GCC 14 packages without a toolchain PPA. The 2026.10.24 release retains its Ubuntu 22.04 build baseline.

For a Linux renderer build with Ninja:

cmake --preset linux-renderer-dev
cmake --build --preset linux-renderer-dev --target rollnw-client mudl
./build-renderer/tools/client/rollnw-client

Use windows-renderer-dev for Windows and macos-renderer-dev for macOS Apple Silicon (which outputs to build-renderer-macos/tools/client/rollnw-client). Library development presets are linux-dev, macos-dev, and windows-dev; see CMakePresets.json for the available configurations.

To work with NWN content, install NWN:EE and any required hak files. If discovery fails, set NWN_ROOT to the game installation and NWN_HOME to its user directory. In the toolset, choose Import Module... on Home. See the toolset guide for the workflow.

Running the tests

The test suite requires an NWN installation. This repository ships no game assets, so the tests read game data from an install rather than from a copy checked in here. The suite refuses to start without one.

Dedicated-server data is enough for everything except renderer work, and scripts/ci/ensure_nwn.sh fetches it (this is what CI uses):

./scripts/ci/ensure_nwn.sh        # downloads to ./nwn
NWN_ROOT=./nwn ./build/tests/rollnw_test

NWN_ROOT can point at any installation containing data/nwn_base.key — dedicated server, GOG, Steam or Beamdog client. Note that the dedicated-server data indexes models, textures and PLT layers but ships zero bytes for them, so tests needing those assets skip unless NWN_ROOT is a full game install.
